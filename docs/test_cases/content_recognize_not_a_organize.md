# 用例：内容识别后分类进新文档 ≠ A 级搬家

| 项 | 值 |
|---|---|
| 日期 | 2026-11-13 |
| 现象 | 用户说「读 Word 内容再分类进各自新文档」，产品却按扩展名/日期**移动文件** |
| 级别 | 接入分流（file_organize）误判 |
| 自动化 | `tests/test_local_file_intent.py::test_veto_content_recognize_then_split_docs` |
| 契约 | `file_organize.veto_patterns` → `V_CONTENT` / `V_WORD_DOC` |

---

## 1. 原话（活测）

```
帮我把现在桌面上的word文档内容识别后，分类整理进各自新文档里
```

用户意图（自然语言）：

1. **读**桌面上 Word 的正文（内容识别）
2. **按内容主题/类别**拆开
3. **写成各自新文档**（产出新文件，不是挪原文件）

实际行为（撤回日志可见）：

- 走了 A 级 `default_pack`（扩展名归档 + 关键词 + **按日期扫尾**）
- 撤回清单里出现：`微信开发者工具.lnk`、`~$WRL….tmp`、`UPDF.lnk` 等  
  → 说明连快捷方式、Office 锁文件都被 `move_date` 收进 `年/月` 目录  
  → **完全没读任何 Word 正文**

---

## 2. 为什么会这样（链路）

接入顺序（`engine/dispatcher.py`）大致是：

```
用户输入
  → local_file_intent.match()     # 契约，0 token，最先跑
       ├─ veto_patterns 命中 → 禁止本地整理，交给模型 / 提示配 Key
       └─ intent_rules 命中 → 直接 A 级搬家（有 Key 也不问模型）
  → （未 hit）才 intent_router / 内容管线 / Word…
```

设计本意：

| 级 | 做什么 | 要不要模型 |
|---|---|---|
| **A** | 只动**文件位置**（扩展名、文件名关键词、日期） | 否 |
| **B+** | **读内容**再摘要 / 分类 / 成稿 | 是（要 Key） |

因此契约里用 **veto** 挡住「像查表 / 改 Word / 内容整理」的口语，避免「整理」二字把一切吞进 A。

### 2.1 旧否决表漏了什么

旧 `V_CONTENT` 大致只认：

- `整理内容` / `内容整理`
- `摘要` / `总结…内容` / `提取…内容` / `生成报告`

用户说的是 **「内容识别」** 和 **「分类整理进各自新文档」**：

| 片段 | 旧 `V_CONTENT` | 说明 |
|---|---|---|
| 内容识别 | ❌ | 词序与「内容整理」不同 |
| 分类整理进各自新文档 | ❌ | 没有「进新文档」类否决 |
| word文档 + 内容识别 | 旧 `V_WORD_DOC` 也 ❌ | 旧规则要「这个 Word / Word 里 / .docx 里」 |

→ **veto 全 miss**。

### 2.2 为什么又命中了 A

兜底规则 `R_DEFAULT_ORGANIZE`：

```
(?:整理|归档|分类|归类)(?!\s*内容)
```

原话里有 **「分类整理」**：

- `分类` / `整理` 命中
- 后面不是「内容」，负向预查通过  
→ **status=hit，rule_id=R_DEFAULT_ORGANIZE**

`default_pack` 编出的动作链：

1. `organize_by_ext` — 按扩展名进「文档/图片/…」（`.docx` 会进「文档」，但**仍是搬家**）
2. `move_keyword` — 文件名含「合同」等
3. `move_date` — **剩余所有文件**按修改时间进 `YYYY/MM`  
   → `.lnk`、`~$*.tmp` 等不在扩展名表里的，全部被这一步扫走  
   → 与撤回列表一致

### 2.3 一句话根因

> **否决短语表过窄 + 兜底「见整理就搬家」过宽** →  
> 「内容识别后再分类进新文档」在字面上撞上「分类/整理」，被当成 A 级位置整理。

不是模型听不懂，而是 **根本没进模型**：本地规则抢先执行了。

---

## 3. 修复（已落地）

契约补强（仍只做机械短语，不猜业务列/主题）：

- `V_CONTENT`：加入 `内容识别`、`识别后…分类/整理`、`分类|整理进(各自)?新文档` 等
- `V_WORD_DOC`：加入 `word文档` + `内容识别|分类整理进|进各自新文档` 等

预期：

| 句子 | 期望 |
|---|---|
| 上文原话 | `veto`（content 或 word），**禁止** A 级搬家 |
| `分类整理` / `按类型整理` | 仍可 `hit`（纯位置整理） |

自动化见同目录对应的 pytest；跑：

```text
python -m pytest tests/test_local_file_intent.py::test_veto_content_recognize_then_split_docs -q
```

## 4. 能力边界（P0 / P1 / P2）

- **P0**：不误走 A、不误进 WordOffice 选文件门闸。
- **P1（已接通）**：顶层 `.docx` → 规则 6 类判别 → 复制到 `内容分类/<类名>/`（原件不动，0 token）。
- **P2A（已接通）**：按标题/章节结构拆段 → `内容拆分/<源>/<切片>.docx`；无切点诚实失败。
- **P2B（已接通）**：模板填槽 → `模板成稿/`；缺槽不瞎填。
- **不做**：长文风格仿写；AI 自由主题聚类。

## 6. 第二失败：否决 A 之后误进 WordOffice

### 现象（活测）

```
帮我把现在桌面上的word文档内容识别后，分类整理进各自新文档里，只动word文档。
→ [WordOffice] 请先在文件管理器里选中一个 .docx 文件，我才能处理。
```

### 为什么

1. A 级 veto 已生效 → 不再搬家（对）
2. 有 Key → 意图模型看到「word」→ 选 `word_office`（错工具）
3. WordOffice **只改选中的那一个** `.docx`，没选中就 fail-closed

### 该怎么修（分档）

| 档 | 做什么 | 状态 |
|---|---|---|
| **P0 近** | 本地识别 → **禁止进 WordOffice / A 级搬家** | ✅ |
| **P1 中** | 扫顶层 `.docx` → 规则判别（6 类）→ 复制到 `内容分类/<中文类名>/`（原件不动）；无 Key；撤回删产物 | ✅ |
| **P2A** | 按标题/章节拆 → `内容拆分/`；无结构则诚实失败 | ✅ `structure_split` |
| **P2B** | 模板填槽 → `模板成稿/`；缺槽 fail-closed | ✅ `template_fill` |
| **仿写** | 长文风格仿写 | ❌ 本刀不做 |

自动化：`tests/test_content_split_batch.py` / `test_content_split_structure.py` / `test_template_fill.py`

### P1 行为要点

- 默认只扫**顶层** `.docx`；指令含「含子目录」则加一层（跳过 `~$`、成稿输出目录）
- 点名「桌面」时尽量解析真实桌面路径
- 新文档 = **按类型复制**；**同内容指纹命中则跳过**（不堆 `_1/_2`）
- 指纹索引**只认输出树现存文件**（撤回删产物后可再生成；不合并陈旧 JSON）
- 清单列：状态 / 类型 / 得分 top2 / **来源** / 新文档 / 跳过原因
- 有效正文不足 80 字跳过；低置信 → `other`（`classify_decision` 统一）；有 Key 才软标签（单轮上限 20）
- 类目单源：`doc_classifier.TYPE_LABELS`（含「其他」）；幂等全跳过时 `ok=True, reason=all_skipped`
