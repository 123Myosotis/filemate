# 站 0 · 双击启动：程序怎么活起来

**这站在干什么**：工作目录切换 → 依赖导入 → 契约库校验 → Qt 应用 → 主窗口。

**去哪读**：`main.py`（全文 77 行）

**问题**

1. `[简]` 为什么 `main.py` 一开头要 `os.chdir(_ROOT)`？
   > 双击运行时工作目录可能不是项目根，不切会导致相对路径找不到文件。
2. `[简]` `sys.path.insert(0, _ROOT)` 解决什么问题？
   > 保证 `import ui.main_window` 这类项目内导入能成功。
3. `[中]` `_fail()` 为什么做了"三层兜底"（Qt 弹窗 → 写日志 + 系统对话框 → print）？
   > 因为失败场景本身可能连 PyQt 都没装；要保证用户**一定看得到**错误。
4. `[中]` `ensure_contract_library()` 校验失败时，为什么**不允许启动**？
   > 契约是权威；契约库坏了，后面所有规则/门禁都不可信。
5. `[坑]` 如果 `config.json` 被写坏，程序会崩吗？
   > 不会——`config.load_config()` 解析失败返回 `{}`（见站 19）。
6. `[难]` 启动顺序里，为什么"契约库校验"在 `QApplication` **之前**？
   > 先把"数据/规则"准备好，再起界面；否则窗口起来了但规则是坏的。

**过关自检**：能画出「双击 → 4 步 → 窗口出现」的流程图。
