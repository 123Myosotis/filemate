## 1. A' 包含关系与层先后的方向约定

采用方案 B。本地只交出矩形与包含 / 互不相交事实。模型输出每个矩形所属的层标识，以及层标识的先后。

**方向约定（实现必须写成同一方向，禁止颠倒）：**

- 「包含」指定位集合上的几何包含：矩形甲的定位集合包含矩形乙的定位集合。
- 「层先后」里，**被包含的矩形所属层，排在包含它的矩形所属层之后**。直观上：外层 / 更大范围在前，内层 / 更小范围在后。
- 校验句：若甲包含乙，则模型给出的层标识顺序中，甲所属层必须出现在乙所属层之前。违反则结构无效，退回模型。本地不改层标识。错误码映射见第 7 节。
- 互不相交的矩形：本地不对它们的层相对顺序做额外约束；先后完全由模型声明。
- 「是否构成一个完整表头」只由模型判断。本地不做。

### 层标识的承载形式

模型返回的层先后采用**一个有序列表**：列表中每一项是一个层标识，列表从前到后即层的先后。

配套结构（抽象）：

- 一份「矩形 → 层标识」的归属映射：每个本层矩形恰好对应一个层标识。
- 一份「层标识有序列表」：无重复；列表下标越小越靠前（外层方向）。

本地做包含一致性比对时：

1. 从归属映射取出甲、乙各自的层标识；
2. 在有序列表里查这两个标识的下标；
3. 若甲包含乙，则甲的下标必须严格小于乙的下标。

禁止改用「每个层自带一个可任意填写的序号」作为校验依据的主形式。若模型同时带回序号，本地仍以有序列表的下标为唯一顺序来源；序号与列表冲突则结构无效（错误码见第 7 节）。

分组标签与层：

- 分组标签是几何字段列范围。可与某层同矩形，语义上不是同一概念。
- 恰好一层 / 跨多层 / 不是任何层：三者都是模型声明。本地只做集合相等、并集相等、包含一致性核对，不删字段、不替模型切开。

继承关系：

- A' 继承矩阵草案几何，不替换、不并行跑第二套几何，不纠正块划分。
- 块划分可疑走冲突通道。本地不得重切块。回滚用**识别回滚点**快照（机制与设计 F 的阶段起点快照相同）：丢弃本识别回滚点及之后的 A' 产物，保留上游草案。补这一条的目的：与 §4 术语统一，禁止再用「阶段」称呼 A'。来自审查意见【顺-4】。

## 2. A' 复核附原文与复杂度上界

复核输入三件套：上游定位、本层输出、附上的单元格原文。

**原文附件的边界：**

- 原文只供模型阅读。本地投影与包含计算不读单元格原文做判断。
- 附原文不等于本地做第二次语义扫描。实现时：附件从本层已经回指到的定位上取已有单元格值，随复核载荷交给模型。
- 复杂度上界不变：只对已收集的合并矩形和已有字段列范围各走一遍；包含关系只在这些矩形上算。不因附原文再扫一遍全表网格。

有序布局无矩阵草案时：不编造层；画像声明上游无此结构。

### A' 复核输入的容量约束

复核输入 = 上游定位 + 本层输出 + 附上的原文。附件可能使序列化长度超过契约容量。

**处理路径（已选定）：模型重出复核范围**——模型给出「本次复核覆盖的定位」子集，使附原文后的复核输入落进契约容量。这里的「范围」指复核覆盖的定位，**不是**重定义层。

选定理由：

- 附件绑定在本层已回指的定位上；缩「这一次复核覆盖哪些定位」是模型的语义决定，与方案 B「本地不改层标识、不替模型切矩形」一致。
- 本轮不改契约，契约里没有现成的「A' 复核附件」机械压缩口径；不能假装走契约压缩，也不能由本地按几何规则自选子集。
- 超容量首先是本次复核附件过大，不是必须立刻问用户的语义冲突；先让模型重出更小的复核定位集合。

#### 「是否已无法再缩」——选定路径 A'（模型声明最小）

补这一条的目的：消除「契约允许的最小可复核单位」无定义。来自审查意见【1】【2】。

**选定：路径 A'。** 模型在给出复核定位标识列表时，可附带结构化声明：「本子集已是可选最小」，并带定位依据（指向已知矩形标识）。本地只校验：声明存在、非空、依据指向已知矩形标识。本地**不**判断是否几何最小。

清单表述：**模型声明已无法再缩仍超容量 → 走冲突通道。**

未采用路径 B'（本地用几何规则判「是否已最小」）。理由：与「模型重出复核范围、本地不决定子集内容」一致；若本地既不选子集又判最小，会引入第二套语义/几何裁量。

硬禁：

- 本地不许截断单元格原文来凑容量。
- 本地不许丢定位或丢层对象来凑容量。
- 本地不许按几何规则自行决定复核定位子集内容。
- **本地不判是否已最小；最小声明由模型给出。**

复杂度：缩范围与退回仍只使用已收集的矩形与字段列范围，以及这些定位上已取到的单元格值。不因容量处理再扫一遍全表网格。本条不改变第 2 节原有复杂度上界。

若模型已声明「本子集已是可选最小」且按该子集重建后仍超容量：结构无效，走冲突通道，由模型在回复里给出下一步。那是同一条退回路径的终点，不是并行的第二条主路径。

#### 第一次「要子集」请求本身超容量

补这一条的目的：消除「要子集」最小请求仍超容量时的死锁。来自审查意见【A-1】。

「要子集」请求体只含：已知矩形标识集合、容量事实、超限事实（不含完整附原文正式载荷）。若**这一请求本身**序列化后仍超过容量：

- A' **不得**在内部循环再缩已知矩形列表（那是本地决定哪些矩形不进本次识别，属语义判断）。
- A' **不得**写「只取前若干个矩形」一类本地缩法。
- A' **立即返回冲突状态**，由调用方走冲突通道（问用户，或按回滚规则回到上游布局/块划分相关回滚点）。
- 与上文硬禁一致：本地不在内部决定任何复核定位子集。

两次模型调用语义、追问轮数、正式复核否决的识别回滚点见证据对应节。

## 3. D' 分次复核自述与证据要求

判断记录：每个字段一条，含字段标识、定位、该批结论。条数不随分组计划变少。

路径分层：

1. 分组导致复核装不下、但记录条数本身仍能一次装下 → 可退回模型重出分组计划。
2. 记录条数本身已超过契约容量 → 不得再退回重出计划（会死循环）。按契约做定位区间压缩，保留全部字段标识、定位、结论；不得按相似压缩。
3. 压缩后仍超 → 按定位顺序分次复核。每一次声明未覆盖的其余标识。
4. **自述强制项**：模型若声称「本片内部无冲突」，必须同时给出结构化自述：本片与哪些尚未复核的字段标识可能需要跨批再看。每条自述必须带证据定位（字段标识 + 定位）。本地只收集并转发，不判断是否真的同义。
5. 全部次数完成后，做一次汇总复核（输入组成见下）。
6. 汇总仍超容量 → 冲突通道终点。不再切开，也不退回分组计划。由模型在回复里给出下一步。

### 尚未复核的标识由本地传给模型

每一次分次复核的输入必须由本地显式附上清单：

- 本批已纳入复核的字段标识及其定位；
- **本批之外、本轮分次复核尚未覆盖的字段标识及其定位**（完整列表，不得省略）。

模型只基于这份清单写自述。模型不得猜测「还有什么没复核」。

若本地未传该清单，或清单缺定位：本次分次复核输入结构无效，退回重出（错误码见第 7 节）。不允许在缺清单的情况下接受「本片无冲突」或空自述并当作通过。

### 汇总复核的输入组成

汇总复核的输入必须同时具备以下三部分，缺任一部分则结构无效，退回重出（错误码见第 7 节）：

1. 各次分次复核给出的自述原文（完整保留，本地不改写语义）；
2. 自述里点到的每个字段标识的定位；
3. 那些字段标识在原批判断记录里的结论。

本地只做机械收集与拼接，不判断哪条自述成立。

禁止把汇总做成「只读自述原文、没有定位、没有原批结论」的空转。

证据要求（实现自检）：

- 缺自述字段、自述为空列表却声称无冲突、自述缺定位 → 结构无效，退回模型。
- 本地不得把「缺自述」当成「无冲突」。
- 本地不得用相似分数或阈值筛自述。

## 4. 实现交付时的其它硬约束（摘要）

- 语义决策只在模型侧。本地只做引用存在性、枚举成员、次数上限校验。
- 冲突是独立介入种类，经现有单回调传输；分发见到冲突种类必须停住。
- 回滚粒度（阶段计划内）：以阶段计划中的阶段为单位；快照在阶段开始前；失败丢弃该阶段及之后产物，不在半成品上补丁。
- **A' 不是阶段计划里的阶段**（A' 在路由之前）。A' 使用同一套回滚机制的另一处落点，术语为**识别回滚点**：正式复核否决或冲突时，丢弃该识别回滚点及之后的 A' 产物，保留上游草案；不是只回滚某个定位子集。不得把 A' 称作「阶段」。补这一条的目的：与设计 F 节「阶段」定义对齐。来自审查意见【B-3】。
- 连接展开必须只膨胀阶段点名的行范围，且任意连接方式的未命中行都可还原到父表、块、列/行定位。
- 每交付一段前：打开反硬编码清单，逐条勾「已检查」或「命中项与处置」，写入当次 EVIDENCE。
- **本次路由实现全程不改契约文件。** 契约枚举残留与旧错误码等，等契约变更单独批准后再处理。

### 调用方对 A' 两失败状态的分支（强制）

补这一条的目的：防止两状态并成一条死路。来自审查意见【阻-3】。

## 7. 「结构无效」与现有错误码映射

补这一节的目的：清单里「结构无效」不得无码可落。来自审查意见【9】【10】。

### 类别 → 具体码名（与 K07 / L01 统一）

补这一条的目的：类别名与具体码名一一对应，避免只写类别。来自审查意见【B-1】。

| 错误码类别 | 具体码名 |
|---|---|
| 提案无效类 | `cross_table_proposal_invalid` |
| 契约无效类 | `cross_table_contract_invalid` |
| 输入无效类 | `cross_table_input_invalid` |

本表凡写「提案无效类」均映射到 `cross_table_proposal_invalid`；凡写「契约无效类」均映射到 `cross_table_contract_invalid`；凡写「输入无效类」均映射到 `cross_table_input_invalid`。与反硬编码清单 L01（容量缺 → 契约无效类 → `cross_table_contract_invalid`）及 K07 口径一致。

### 两码边界（定义）

| 错误码类别 | 定义 |
|---|---|
| 契约无效类 | 契约应提供的能力/枚举/上限缺失或形态非法，或调用方未按契约能力传入必填上限 |
| 输入无效类 | 运行时业务输入结构不完整、引用不存在、集合条目缺失等，与契约文本是否齐全无直接关系 |
| 提案无效类 | 模型返回的结构不满足本层校验（缺字段、集合矛盾、声明与已知标识对不上等） |

调用方传入非法的复核输入容量（缺省、非正整数等）：属**契约无效类** / `cross_table_contract_invalid`。

#### 回调缺省与容量缺省为何不同码（顺-5）

补这一条的目的：同一「调用方未注入」不得静默混码。来自审查意见【顺-5】。

**选定：维持分码，并写清理由（不统一成契约无效类）。**

| 缺省项 | 码 | 理由 |
|---|---|---|
| 复核输入容量 | 契约无效类 | 属契约能力清单应承载的上限；缺 = 契约能力未落地（与 L01 一致） |
