# 项目架构（A–E）

> **唯一架构文档**。只用 **A–E** 分层，不提 L0–L3（那是历史名，已废弃）。
> 从上到下：用户 → 接入层 → 任务链 → 执行层（A–E）→ 记忆 → 输出。

## 两个维度（**替代 L0–L3**）

| 维度 | 用 | 量什么 |
|---|---|---|
| **任务** | **A–E**（§1） | 这个活**多重**（token / AI 强度） |
| **改写** | **`op_type`**（`contracts`） | 这次**改什么**（replace / insert / delete / format / move / tracked_change） |

**L0–L3 = 规格历史名**；**L2/L3 = `op_type` 的 `move` / `tracked_change` + 跨结构**。
**不是"把 L0–L3 塞进 A–E"**（量的不是一回事）。

## 1. A–E 五级

> 术语边界：A–E 是**任务强度分级**（规则 / 轻 AI / 中 AI / 强 AI / 分块）。
> 能力层（适配 / 确定性 / 语义编辑 / 内容理解 / 内容生成 / 批量）不要复用这组字母，避免同一组字母出现两套含义。详见 `docs/text_pdf_module_design.md` §2。

| 级 | 任务 | LLM | 上下文 | 典型 token |
|---|---|---|---|---|
| **A. 规则** | 整理 / 归档 / 重命名 / 按扩展名分类 | **无** | 文件名/扩展名 | **0** |
| **B. 轻 AI** | 内容识别 / 摘要 / 分类 | **小** | 文件摘要 | **1~2K** |
| **C. 中 AI** | 改写 / 仿写 / 润色 / 风格识别 | **中** | 段落 + 结构 | **4~8K** |
| **D. 强 AI** | 标书 / 合同 / 大纲生成 | **强** | 模板 + 素材 | **16~32K** |
| **E. 分块/多文件** | 超大文件 / 一批文件 | **中** | 分块 + 块摘要 | **按块** |

**A 级留升级口**：规则不够 → 升级 B（和 `semantic_match` 同一模式）。

**接入分流（file_organize）**：契约 `file_organize.intent_rules` 命中 → **0 token、无 Key 可走**（有 Key 也不调规划/复核模型）；`veto_patterns` 命中（表 / Word / 内容 / 咨询）→ **禁止**本地整理。`table_query` / `word_office` / 内容整理 **必须有 Key**，本地不猜。规则对上但当前目录编不出移动清单、且已有 Key → **升级给模型**，不把空清单当成最终失败。

## 2. 任务链（**线性**，单动作不走）

### 2.1 触发条件（**不走链占多数**）

| 情况 | 走不走链 | 理由 |
|---|---|---|
| **单动作**（整理桌面 / 润色 / 做标书） | **不走** | 直接 A–E |
| **多动作同类**（10 个 Word 都摘要） | **不走**（**串行循环**） | 循环 ≠ 链 |
| **多动作有序**（识别 → 汇总 → 归档） | **走线性链** | 有先后 |
| **多动作可并行** | **走线性**（串行跑） | 并行收益小、复杂度高 |

### 2.2 形状：**先线性，后按需 DAG**

| 形状 | 何时 | 代价 |
|---|---|---|
| **线性**（`t1→t2→t3`） | **默认（v1）** | 简单、可预测 |
| **串行循环**（一批文件） | v2 | 简单 |
| **DAG**（并行/分支） | **仅当实测并行收益 > 复杂度**（v3） | 需要调度器，重 |

### 2.3 判据（伪代码）

```python
tasks = intent.get("subtasks")
if len(tasks) <= 1:
    return execute_single(tasks[0])     # 单任务：直接执行
else:
    return run_linear(tasks)            # 默认为线性链
```

## 3. 弹窗询问（低置信 / 危险操作）

### 3.1 触发条件

| 条件 | 弹窗？ |
|---|---|
| **置信度 ≥ 0.8** | **不弹**（按判） |
| **0.5 ≤ 置信度 < 0.8** | **弹窗**（选任务/确认） |
| **置信度 < 0.5** | **弹窗**（必须问） |
| **危险操作**（删除 / 覆盖） | **弹窗**（确认） |
| **文件树「整理」按钮** | **弹预览**（无口令，default_pack 覆盖面大，特异度低） |
| **聊天命中 A 级 intent_rules** | **不弹**（高置信、0 token） |

### 3.2 形式（PyQt6，像权限询问）

```
┌─────────────────────────────────────────────┐
│  我需要确认一下                             │
│                                             │
│  你是想要：                                 │
│   ○ 整理/归档这些文件（A 级，不花钱）       │
│   ○ 识别并生成报告（C/D 级，约 8K token）   │
│                                             │
│   [ ] 记住我的选择（下次不再问）            │
│                                             │
│        [取消]        [确定]                 │
└─────────────────────────────────────────────┘
```

### 3.3 权衡

| 利 | 弊 |
|---|---|
| 避免**误判**（意图错 → 用错模型） | **打断**用户（频繁弹窗烦） |
| 危险操作**有闸门** | 需要 **UI 线程**（PyQt6 弹窗） |

**优化**：**只在低置信/危险时弹**；**提供"记住选择"**（下次不弹）。

## 4. 记忆（即时 / 后台）

> 记忆分层以本节为准（历史稿 `构建/记忆设计.md` 已随仓库旁路收口移除）。

| 类型 | 范围 | 存储 | 检索 | 淘汰 |
|---|---|---|---|---|
| **即时记忆** | 当前对话/当前任务 | 内存（session） | 直接 | 任务结束 → 归档 |
| **后台记忆** | 跨任务/长期 | SQLite | FTS5 + dense | 热度/floor/降级 |

**关系**：**即时**（快、易失）→ 任务结束 → **归档**到**后台**（摘要/术语）。

### 4.2 用户纠正（P2，接入层）

| 记 | 不记 |
|---|---|
| 用户明确答过的二次洗（洗 / 不洗 / 表头） | 危险 Word 操作（每次仍确认） |
| 同一 `path` + 表名 + **文件指纹** | 指纹变了当 miss，重新问；用户可说「忘记这次洗表选择」revoke |
| 生命周期 active / invalidated / revoked | **有意**不把 Excel `memory_rag` 与 Word `memory.py` 合成一张表 |

**不碰文件**。没有纠正样本不上自动学习。

### 4.1 上下文预算（**memory 取几条**，不写死）

| 项 | 规则 |
|---|---|
| **条数上限** | **契约** `word_office.memory_related_max`（默认 3） |
| **长度上限** | `ai.context_budget.effective_input_chars()` × **20%**（记忆段最多占 prompt 两成） |
| **超预算** | **先减条数，再截断摘要**（不硬塞） |
| **缺失** | 契约缺 → 回退 3（**有据可查**，不是随手写） |

**代码**：`module._memory_related_max()` 读契约；`module._memory_blob()` 按预算截断。
**为什么**：`related[:3]` 是**魔法数**（没出处、改不了）；**契约化后**改上限**不用改代码**。

## 5. 不碰文件边界

| 层 | 碰不碰文件 |
|---|---|
| **记忆（小脑）** | **绝不碰**（只读/只写记忆表） |

**一句话**：**"不碰文件"= 记忆的约束；主功能写文件是允许的（有保护）。**

## 6. 自审

| 项 | 结论 |
|---|---|
| **矫枉过正** | 否——**线性链 + 最简记忆**，都是最小可行 |
| **违背初衷** | 否——失败整批拒绝；A 级 0 成本；记忆不碰文件 |
| **技术利弊** | **利**：简单、可预测、成本低；**弊**：线性不并行（慢一点）、后台记忆要维护（热度/淘汰） |

## 7. 七个机制（Boot / Pre-check / Fingerprint / Review / Evidence / Return / Report）

| # | 机制 | 时机 | 做什么 | 现在 |
|---|---|---|---|---|
| **1** | **Boot**（启动校验） | 启动 | `word_office` 分区必须存在（`ensure_contract_library` 加一行） | ✅ 加一行 |
| **2** | **Pre-check**（门 + 校验 + 预算） | **执行前** | `tier ∈ A-E` / `ops 白名单` / `find` 非空 / `≤20` / `预算` | ✅ 合并 |
| **3** | **Fingerprint**（指纹） | 执行前/后 | `file_sha256` + `structure_sha256`（检测，不拦） | ✅ |
| **4** | **Review**（后置审查） | **执行后** | 结构不变 + 内容对账（`find→0`） | ✅ 已有 |
| **5** | **Evidence**（证据） | **执行后** | 本地 JSON（30 天清理） | ✅ |
| **6** | **Return**（返回结构） | 返回 | `status / stages[] / fail_locus / tokens / warnings[]` | ✅ 改结构 |
| **7** | **Report**（报告） | **D/E 输出** | 复用 `export/word_renderer.py` | ✅ **严闸门**（只 D/E + 真实写成功；E 还要 batch/emit 旗；A/B/C 绝不出） |

### 7.1 合并说明

- **Gate + Validation + Budget** → **Pre-check**（一次校验，不重复跑）。
- **Review** 保持**后置**（结构 + 内容）。
- **Budget** **不单独**（在 Pre-check 里）。

### 7.2 每个机制的边界（防矫枉过正）

| 机制 | 不做（防矫枉过正） |
|---|---|
| **Pre-check** | 不照搬 Excel 的 **DSL 门**（binding/join/scope）；**超预算只提示**，不硬拒 |
| **Fingerprint** | **只检测**，不硬拦（结构变可能是合法修改） |
| **Review** | 结构不变只对 **A 级**是硬门；**B–E 软提示** |
| **Evidence** | **本地 only**（不上传）；自动清理 |
| **Report** | **只 D/E**；且须写成功（applied>0 + committed）；E 另要 batch/emit 旗；A/B/C 不做 |

### 7.3 优先级

| 优先级 | 机制 | 改动量 |
|---|---|---|
| **P0** | **Boot** / **Pre-check** | 极小 / 小 |
| **P1** | **Fingerprint** / **Return** | 小 / 小 |
| **P2** | **Evidence** / **Review**（AI opt-in） | 中 / 中 |
| **✅** | **Report**（只 D/E，严闸门） | 已接 `pipeline/word_office/report.py` |

### 7.4 自审

| 项 | 结论 |
|---|---|
| **矫枉过正** | 否——**9 合并为 7**；**Pre-check 只 5 项**；**Report 只 D/E** |
| **违背初衷** | 否——**超预算只提示**；**指纹只检测**；**证据本地** |
| **技术利弊** | **利**：防非法 op + 成本可控 + 可追溯 + 可观测；**弊**：白名单要维护 / Evidence 占盘 / AI 复核额外调用（opt-in） |

### 7.5 弊的优化（每条"弊"的解法）

| 弊 | 优化 | 代价 | 优先级 |
|---|---|---|---|
| **白名单要维护** | **移到契约** `word_office.ops_whitelist` + `authority_scan` 守 | 低 | **P0** |
| **Evidence 占盘** | **gzip** + 30 天轮转 + **摘要进 DB / 明细进文件** | 低 | **P1** |
| **AI 复核贵** | **只 D/E**；或**只本地失败时**；或**抽样 10%** | 低 | **P2** |
| **超预算只提示（浪费）** | **`hard_budget` 开关**（默认关，开了硬拒） | 低 | **P0** |
| **指纹只检测** | 检测到"文件被改" → **提示"建议重扫"**（不硬拦） | 低 | **P1** |
| **线性链慢** | **E 级多文件并行**（独立文件，`ThreadPoolExecutor`） | 中 | ⏳ **后** |
| **记忆膨胀（用户不点）** | **超 30 天未维护 → 自动降级（不删）** | 低 | **P2** |

**一句话**：**"弊"都有解，且大多零成本**（移契约 / 压缩 / 开关 / 降级），**只有"多文件并行"要后做**。

## 8. 复用原则（**先比对，再决定**）

> **"复用"不是"搬代码"**——先看**能不能复用**，再比**谁更好**；**不能无视 Excel ≠ Word**（一个表格、一个文本，运行逻辑不同）。

| 步 | 做什么 |
|---|---|
| **1. 比对** | 把 Excel 的**能力/实现**与 Word 的**需求**逐项比：**谁更好、是否适用** |
| **2. 判定** | **能复用**（逻辑一致）/ **部分复用**（抽象后）/ **不能复用**（逻辑不同） |
| **3. 落地** | **能复用**：抽公共层或 **adapter**；**不能**：Word 独立实现 |
| **4. 红线** | **Excel 代码不能碰**（只读、只调，不改） |

**三条红线**：
1. **不无视 Excel ≠ Word**（表格 ≠ 文本）。
2. **Excel 代码不能碰**（只通过**接口/adapter** 用）。
3. **不能为了复用而扭曲**（Reuse 不能改变原语义）。

## 9. 记忆（小脑）——**三者要分开**

> **这是最容易搞混的地方**：**设计、Excel 实现、我的实现**，**不是同一个东西**。
>
> **裁定（2026-11-12）**：Excel / Word **两套记忆是正确设计，不换成一套**。可抄格式与生命周期，不可合成一张表、不可为复用扭曲语义。接入层的 `memory_choice`（洗表纠正）是第三类、更窄的「记住选择」，也不并进小脑。

### 9.1 三者对照（**互不相等**）

| # | 名称 | 是什么 | 位置 | 优点 | 缺 |
|---|---|---|---|---|---|
| **1** | **Excel 的记忆** | `memory_rag`（术语/召回/语义/审计） | `block_cross_table/memory_rag/`（41 文件） | **具体、已实现** | **文件主题 / 即时 / 做梦** |
| **2** | **设计上的小脑** | 历史设计稿（已移除） | 曾在 `构建/` | **架构更好**（通用/分层） | **没落地；以 §4 / 本节为准** |
| **3** | **我的实现** | `memory.py` + `session.py` | `pipeline/word_office/` | **Word 可用**（文件主题 + 即时） | **没接术语/召回** |

**关系**：**1 ≠ 2 ≠ 3**；**1 是 2 的一个实现（Excel 版）**；**3 是另写的（没按 2）**。

### 9.2 Word 记忆 = **（3）底座 + 抄（1）格式 + 按（2）架构**

```
word_memory（Word 自己的表）
  ├── file（文件主题：hash/summary/keywords）      ← 我的，保留
  ├── session（即时）                              ← 我的，保留
  ├── term（术语）                                 ← 抄 Excel 的 jargon 结构
  ├── term_anchor（术语↔锚点）                      ← 抄 binding，改语义（Word 独有）
  ├── recall（FTS5，后期可加向量+RRF）              ← 抄 hybrid_recall
  └── lifecycle（active/invalidated/revoked）       ← 抄
```

### 9.3 **必抄 / 选抄 / 不抄**

| 类 | 抄什么 | 理由 |
|---|---|---|
| **必抄** | **术语表结构**（term/aliases/weight） | Word 有黑话 |
| **必抄** | **生命周期**（active/invalidated/revoked） | 任何记忆都要淘汰 |
| **必抄** | **`term_anchor`（术语↔锚点）** | **Word 特有**，Excel 没有，**必须新设计** |
| **选抄** | **混合召回**（FTS5+向量+RRF） | 看 Word 要不要**语义召回**（要 embedding） |
| **选抄** | **语义等价** | 同上 |
| **不抄** | **egress/allowlist** | Word 不外发 |
| **不抄** | **列名/表结构** | Word 无列 |

### 9.4 Word **独有**（Excel 没有）

| 项 | 说明 |
|---|---|
| **术语↔锚点** | 术语在**哪个段落/表格/标题**（Excel 是"术语↔词条"） |
| **文件主题** | `memory.py` 已有（Excel 没有） |
| **即时** | `session.py` 已有（Excel 没有） |

### 9.5 优先级

| 序 | 做什么 | 理由 |
|---|---|---|
| **1** | **底座**（file + session） | 已有，**保留** |
| **2** | **术语 + 术语↔锚点**（必抄 + Word 独有） | **最小可用** |
| **3** | **生命周期** | 淘汰 |
| **4** | **混合召回**（按需） | **后加**，不是起步必需 |

**结论**：**小脑是设计（2）；Excel 是它的一个实现（1）；Word 的是我另写的（3）——要用（3）做底座，抄（1）的格式，按（2）的架构，补（1）缺的"文件主题/即时/做梦"。**
