## 一、Word 操作（op）

| # | 优化 | 现状 | 目标 | 利弊 |
|---|---|---|---|---|
| 1 | **`format` 跨 run** | 只 run 级（跨 run 的**不处理**） | 合并 run + 改 `w:rPr` | 利：格式一致；弊：**要动 XML，复杂** |
| 2 | **`format` 字体/字号/颜色** | 只有**粗体/斜体** | 加 `size`/`font`/`color` | 利：能力全；弊：**regex 复杂** |
| 3 | **`delete` 粒度** | 删**含目标文本的整段** | 可选"仅文字"/"整段" | 利：精确；弊：**要用户明确** |
| 4 | **`insert` 支持"前面"** | 只有"后面" | 加"在 X 前面插入" | 利：灵活；弊：regex 复杂 |
| 5 | **`move` / `tracked_change`** | ❌ 未做 | 后 | — |
| 6 | **`insert` 位置精确到 run** | 段落级 | run 级插入 | 利：精确；弊：复杂 |

## 四、技术弊端（**已实现，但有坑**）

| # | 弊端 | 来源 | 影响 | 缓解 |
|---|---|---|---|---|
| 1 | **术语挖掘 n-gram 会漏/多** | `mine_terms` | 无分词/词性 → 候选不准 | **只当候选**，人工确认 |
| 2 | **`format` 只 run 级** | `_exec_format` | ~~跨 run 不生效~~ | ✅ **已改**（跨 run + 字号/字体） |
| 3 | **`delete` 删整段** | `_exec_delete` | ~~粒度粗~~ | ✅ **已改**（只删文字，保留前后） |
| 4 | **`insert` 段级** | `_exec_insert` | 不能 run 内插 | 待办 |
| 5 | **`_plan_ops` 正则** | 关键词 | 表达受限 | 待办：规则表 |
| 6 | **`memory.py` 重写漏函数** | 4.1 → ② | `touch`/`search` 丢失 | **已补** |
| 7 | **FTS 不同步** | ② | 检索漏 | **已补**（`save_file_memory` 同步） |
| 8 | **`upsert_term` 稳定哈希** | ② | 同一术语 **ID 稳定**，但**改术语文本 = 新 ID** | 可接受 |
| 9 | **`recall` 两路都是字面匹配** | ③ | **FTS5 + LIKE 都是字面** → **没有语义召回** | **等 embedding**（写 `ai/embed.py` 后加第三路） |
| 10 | **术语挖掘只挖"候选"** | `mine_terms` | **无分词/无词性** → 会漏（分不出词）也会多（n-gram 碎片） | **必须人工确认**，不可自动当"术语" |
| 11 | **向量全量余弦** | `_vec_hits` | 表大就慢（O(n) 逐条算） | 后加 **ANN / 先粗排**（FTS 预筛再算向量） |
| 12 | **embedding 网络成本** | `ai/embed.py` | 每次 `recall` 都要调一次 | **只对新文件算一次**，缓存 `memory_vec` |
| 13 | **`tracked_change` 段内格式丢失** | `_exec_tracked_change` | ~~清空原 run 重建~~ | ✅ **已改**（拆 run + 复制 `w:rPr`） |
| 14 | **`tracked_change` 只做段级** | 同上 | ~~不能"只修订某几个字"~~ | ✅ **已改**（run 级 `w:del`/`w:ins`） |
| 15 | **`move` 只做段级** | `_exec_move` | 不能跨表/跨节移动 | **待办**（段级是对的，不硬改） |
